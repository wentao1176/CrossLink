# CrossLink development rules
All development, installs, tests and builds run via SSH in /home/CrossLink. No local generated artifacts. Preserve the user-provided docs/DEVELOPMENT_DESIGN.md as the requirements authority.
API prefix /api/v1; database entity IDs are UUIDs. Check ownership on every device/message/receipt/file/transfer operation. Websocket events use event/event_id/timestamp/data; clients send auth after connection, never in the URL. Persist messages before publishing and keep receipts per device. No plaintext passwords or token/clipboard logging. Network operations require timeouts and websocket reconnection. Files require bounded upload, cancellation and cleanup. Endpoints are user configuration, no hardcoded public server. Test new business behavior and update CHANGELOG.md. Keep one API worker until a Redis message bus is implemented. No public listeners or firewall/security-group changes without the user's later request.
